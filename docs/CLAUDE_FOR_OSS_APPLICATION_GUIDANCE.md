# Claude for Open Source: Application Preparation

This repository is prepared to make genuine technical work easier to review. It must not be used to claim impact, metrics, contributor activity, account age, or eligibility that cannot be verified from public evidence.

## What the official program reviews

The published terms require general eligibility, an established GitHub account, recent public open-source contribution activity, and at least one qualifying maintainer-track threshold or a credible ecosystem-impact case. The application asks for a brief description of project reach and impact and a separate explanation of intended subscription use.[1]

| Application field                 | Evidence to use                                                                                                                                   | Do not do                                                                                                        |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| Project reach and impact          | Verifiable package downloads, dependent repositories, external contributors, merged pull requests, public adopters, or documented ecosystem need. | Do not treat a new repository, generated commits, or unverified claims as impact.                                |
| Why the applicant qualifies       | The applicant’s real maintainer/contributor history and links to supporting public evidence.                                                      | Do not invent contribution counts or claim a threshold that is not met.                                          |
| How the subscription will be used | Concrete maintenance work: tests, accessibility, security reviews, documentation, issue triage, releases, and contributor support.                | Do not promise work that cannot be maintained or frame ordinary product development as existing ecosystem reach. |

## Application outline

Use this outline only after replacing each bracketed section with truthful, linkable evidence.

> **Project impact:** I maintain or substantially contribute to [project and URL]. Its practical role is [specific problem solved]. Public evidence of use or contribution includes [verifiable metrics/links]. My role is [maintainer, committer, contributor] and my recent public work includes [specific contributions within the last 90 days].
>
> **Use of Claude Max:** I will use the subscription to [specific maintenance tasks], including [tests, issue triage, documentation, release work, security review, or contributor support]. The goal is to improve [specific measurable maintainability or user outcome] while keeping review and security decisions under maintainer control.

## Repository checklist

- A clear README explains the purpose, architecture, setup, validation, and present production boundaries.
- Contribution and security guidance explain how external work can be reviewed safely.
- The license must be explicitly selected by the project owner and be OSI-approved if the applicant relies on the program’s licensing requirement.[1]
- CI must run the published test and build commands for pull requests and pushes.
- The application should link to only real public evidence and should not claim that this repository alone meets any published metric.
